# Journal des décisions

Ce fichier consigne les choix faits quand la spécification est muette, ambiguë ou
contradictoire, selon la procédure de `CLAUDE.md` : d'abord l'hypothèse de la
section 15 (H-01 à H-57) ; sinon le choix le plus simple compatible avec les
sections 6 et 12.3, consigné ici.

Chaque entrée porte : date, section concernée, question, choix retenu, raison.

| Date | Section | Question | Choix retenu | Raison |
| --- | --- | --- | --- | --- |
| 2026-10-07 | CLAUDE.md socle | Version de Quarkus (« dernière version stable ») | Quarkus 3.40.1 | 4.0 n'existe qu'en Beta ; 3.40.1 est la dernière version stable de la ligne 3.x. La 3.29.4 d'abord essayée référençait une classe SBOM absente et échouait au goal `build`. |
| 2026-10-07 | 12.2 patron BaseEntity | Où placer `entity_id` du cloisonnement | `BaseEntity` ne porte que les colonnes communes à **toutes** les tables (id, version, created_at, created_by, updated_at) ; `entity_id` est déclaré sur les entités concernées, pas dans `BaseEntity` | La convention 5.7 exclut `entity_id` des référentiels partagés entre entités ; le mettre dans la base le rendrait obligatoire partout. |
| 2026-10-07 | TESTS-E2E / `/api/test` | Reset de base et chargement de jeux de données nommés dès l'étape 0 | Mécanisme `/api/test` livré à l'étape 0 avec le seul pilotage de l'horloge (ping, fix, reset) ; reset de base et jeux de données ajoutés à l'étape 1 avec les premières entités et chargeurs | La règle de couverture à 100 % des branches interdit d'écrire une logique « trouvé / introuvable » ou une boucle de troncature tant qu'aucune entité ni aucun chargeur n'existe : une seule branche serait exerçable. |
| 2026-10-07 | TESTS-E2E §1 environnement | « Une instance d'application par processus de test, sur son propre port » | À l'étape 0 : une seule instance dev partagée, lancée par le `webServer` de Playwright (via `run-dev-app.sh`), `workers=1` | Avec un seul fichier de tests, le parallélisme n'est pas exercé ; l'isolation par instance et par port sera mise en place quand le nombre de tests le justifiera. **Fragilité à lever** avant que la suite grossisse. |
| 2026-10-07 | 12.2 / profils | Cible d'exécution des tests E2E alors que la cible est PostgreSQL | L'app est empaquetée et lancée en profil `dev` (H2 en mémoire) pour l'E2E ; PostgreSQL reste la cible documentaire jamais exécutée (CLAUDE : « jamais de production ») | Le point d'accès `/api/test` est conditionné au profil `dev` (`@IfBuildProfile`) ; l'E2E doit donc tourner sur un paquet dev, conforme à « tout tourne en profil dev ». |
| 2026-10-07 | 5.7 / 12.1 packages | Où placer les 68 entités et les énumérations | Toutes dans le package `domain` ; les packages de comportement (`rules`, `engine`, `cycle`, `accounts`, `payment`, `accounting`, `security`, `integration`, `api`) les référenceront | La liste de packages figée de CLAUDE n'offre pas de home pour chaque groupe d'entités (p. ex. pas de package forces de vente) ; `domain` porte le modèle, cohérent avec « modèle de domaine » (section 5). |
| 2026-10-07 | 5.7 conventions | Mapping des colonnes `jsonb` et `varchar[]` portable H2/PostgreSQL | `jsonb` en `@JdbcTypeCode(SqlTypes.JSON)` avec `quarkus.hibernate-orm.mapping.format.global=ignore` ; `trigger_event_types` (`varchar[]`) en JSON `List<String>` ; colonnes texte longues (`raw_line`, `content`) en `varchar(10000)` | H2 n'a pas de type `varchar[]` portable ; le JSON d'Hibernate est portable entre H2 et PostgreSQL ; `mapping.format.global=ignore` évite d'utiliser le formatage JSON REST pour la base. |
| 2026-10-07 | 5.7 conventions | Colonnes nommées d'après un mot réservé (`value`) | `quarkus.hibernate-orm.quote-identifiers.strategy=all` | `value` est un mot réservé en H2 et PostgreSQL ; le quoting global rend le schéma portable sans renommer les colonnes de la spécification. |
| 2026-10-07 | 5.7 (`advance_position.close_reason`, `production_counter`/`rule_condition.counter_code`) | Énumération ou texte libre | `close_reason` et `counter_code` mappés en `String` (non énumérés) | La spécification admet pour `close_reason` un code figé **ou** le code d'un événement de rupture, et pour `counter_code` « un libellé libre défini par la règle » : ensembles de valeurs ouverts, incompatibles avec une contrainte d'énumération. |
| 2026-10-08 | 3 / dev | Authentification dev (SSO simulé) | Utilisateurs déclarés en configuration avec leurs **groupes d'annuaire** ; rôles et entités déduits de la table `role_mapping` éditable, résolus à chaque connexion (HTTP Basic, `DevIdentityProvider` hors prod) | Fidèle au modèle de la section 3 (« rôles et entités déduits des groupes ») et rend l'exigence ADM-01 réellement démontrable (un changement de correspondance modifie les droits à la connexion suivante). |
| 2026-10-08 | 12.1 packages | Où placer les services d'administration des référentiels | `EntityAdminService` dans `integration` (gestion des référentiels, étape « Référentiels et intégration ») ; `RoleMappingAdminService`, `AuditQueryService`, `AuditService` dans `security` ; ressources REST dans `api` | La liste de packages de CLAUDE n'a pas de package « référentiels » distinct ; `integration` porte la gestion des référentiels, `api` les points d'accès REST, `security` l'administration transversale et l'audit. |
| 2026-10-08 | 13 / TESTS-E2E | CR-71 (séparation des tâches) à l'étape 2 alors que l'écran d'approbation des versions de règle est à l'étape 4 | Mécanisme de séparation des tâches (`SeparationOfDuties`) et **test unitaire `cr71`** livrés à l'étape 2 ; le **rejeu par l'interface** (`@cr:CR-71`) est livré à l'étape 4 avec l'écran d'approbation d'une version de règle | Aucun objet à double signature n'a d'écran d'approbation avant l'étape 4 ; le mécanisme et sa vérification unitaire sont néanmoins en place dès l'étape 2, comme l'attend le plan. |
| 2026-10-08 | 12.2 / Quinoa | Un mapper global sur `jakarta.ws.rs.NotFoundException` cassait le routage SPA (routes profondes renvoyaient un 404 problem+json) | Exception métier dédiée `ResourceNotFoundException` mappée en 404 ; `jakarta.ws.rs.NotFoundException` non interceptée, laissant les routes non-API retomber sur `index.html` servi par Quinoa | Enregistrer un mapper pour `NotFoundException` fait revendiquer par Quarkus REST toutes les requêtes non appariées, au détriment du fallback SPA. |
| 2026-10-08 | Tests / couverture | Le code exercé par les `@QuarkusTest` n'était pas comptabilisé par JaCoCo | Extension `quarkus-jacoco` (scope test) réutilisant le fichier d'exécution de l'agent Maven (`quarkus.jacoco.reuse-data-file=true`, `report=false`) | Les `@QuarkusTest` chargent les classes applicatives dans le classloader Quarkus ; sans l'extension, leur couverture est perdue et le seuil à 100 % échoue à tort. |
